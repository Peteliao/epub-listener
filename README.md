# 书声 · 网页听书

**把 EPUB、TXT、MOBI、AZW3、FB2 电子书变成有声书。** 免费、纯前端、移动优先的网页听书工具：导入电子书后逐句朗读并同步高亮，支持系统语音与离线 AI 中英文音色。中文、英文音色包可以同时使用，朗读中英混排；选择离线音色后，iPhone 锁屏也能继续听。不用安装 App，书籍与阅读进度只保存在本机，没有后端、不上传内容。

**在线使用：** https://peteliao.github.io/epub-listener/

书声是一个开源的 **EPUB 朗读器 / TXT 转语音 / 电子书转有声书** 工具，支持 **iPhone 锁屏听书**、**中英混读** 与离线语音合成，在 iPhone、iPad、Android 手机和电脑浏览器里打开即可使用。

## 为什么选择书声

- **免费、免安装**：打开网页就能听，也可以添加到主屏幕当 App 用
- **iOS 锁屏续读**：使用离线 AI 音色时，iPhone Safari 与主屏 PWA 锁屏后仍可继续朗读，锁屏界面能播放、暂停和切换句子
- **中英混读**：中文音色与英文离线音色 Kristin 可同时使用，中英混排按语言片段自动切换；英文也可改用系统英文音色
- **隐私优先**：书籍、阅读进度和设置只保存在浏览器本机，没有账号、没有云端
- **中英文听感优化**：中文多音字、轻声与专名读音按整书语料持续校核，配有人工核过的读音覆盖表，并可按当前电子书自动生成补充读音；数字、单位、日期和电话号码规范化；英文数字、日期、货币和缩写转成英文读法，生词按字母拼读
- **离线可用**：下载中文或英文音色包后，断网也能朗读；中英混排同样可以全离线
- **跨设备**：手机、平板、电脑的现代浏览器都能用，无需装扩展

## 支持哪些电子书格式

| 格式 | 支持情况 | 说明 |
| --- | --- | --- |
| EPUB | 支持 | 基于 epub.js，保留原书排版、目录、插图与内链 |
| TXT | 支持 | 自动识别章节标题并分节，适合网络小说、纯文本读物 |
| MOBI | 支持 | 基于 foliate-js，支持未加密的 MOBI |
| AZW3 | 支持 | 基于 foliate-js，支持未加密的 KF8 / AZW3 |
| FB2 | 支持 | 基于 foliate-js，支持 FictionBook 2 |

单个文件上限 200 MB；带 DRM 保护的电子书无法打开。

## 功能

- **多格式书架**：EPUB / TXT / MOBI / AZW3 / FB2 导入与书架管理（IndexedDB 本地存储）
- **书架封面**：EPUB / FB2 / MOBI / AZW3 自动读取书内封面；TXT 或无封面书籍使用渐变书脊，封面也只保存在本机
- **逐句朗读与高亮同步**：电脑上点击、手机上轻点正文任意句子，立即跳到该句，播放中则从该句继续朗读
- **中英混读**：中文使用中文音色，英文优先使用离线 Kristin；未下载英文包或启动失败时自动回落系统英文音色。英文音量（60%–120%）与英文语速（0.6–1.4×）独立调节，离线英文同样生效
- **双朗读引擎**：系统语音 / 离线 sherpa-onnx AI 音色
- **iOS 锁屏续读**：离线 AI 音色通过媒体元素播放，iPhone 锁屏后继续朗读；锁屏界面显示书名、章节，并支持播放、暂停与上一句/下一句
- **锁屏跳过英文**：iOS 锁屏且英文走系统语音时自动跳过英文段，解锁后恢复并提示跳过段数；英文使用离线音色时不受影响（默认开启，可关闭）
- **离线音色库**：山岚、小雅（仅限非商业）、初晴（可商用）、AISHELL-3 精选（Apache-2.0）共 7 种中文声音，另有英文 Kristin（LibriVox 公有领域录音）；中英文音色可同时驻留
- **中文读音覆盖**：山岚音色内置人工核过的多音字覆盖表，兼顾专名、轻声与容易读错的词组；打开书后会按本书正文自动生成补充读音并缓存在本机，遇到漏网的读法可在「读音反馈」里标记、导出候选，人工复核后再合并
- **英文朗读优化**：数字、年份、日期、时间、货币、小数、序数、常见缩写与符号自动转写成英文读法；词典外的生词按字母拼读，避免英文数字和人名被静默跳过
- **句组连读**：把同段短句连成句组合成，减少句间断裂；停顿支持「紧凑 / 标准 / 舒缓」三档
- **朗读节奏优化**：对话引号独立成句，省略号按句末、破折号按从句停顿；数字、百分比、小数、分数、时间、负号、km/h、㎡ 类单位和电话号码自动转成中文读法
- **剩余听书时间**：根据实测合成速度和音频时长，在进度旁显示「本章剩约 N 分钟」
- **听书时光与分享卡**：只在真实播放时计时，按天与按书记录累计时长、今日、连续天数；书架和阅读设置里可生成跟随阅读主题的分享海报（书名可隐藏，含扫码二维码），手机直接调起系统分享，桌面可保存图片。统计只保存在本机
- **低端机自适应**：连续多个句组合成偏慢时提示切换系统语音或关闭连读模式
- **打开即预热**：在音色包已缓存、设备内存充足且非移动网络时，打开书后空闲预热引擎，减少首次播放等待
- **睡眠定时**：倒计时或指定时刻自动暂停
- **口袋模式**：极简全屏，双击暂停/继续，长按 1.5 秒退出
- **PWA**：可添加到主屏幕，应用壳离线可用
- **新手引导与重看**：首次打开书架、阅读器会分步介绍导入、播放、正文点按、语速、目录、睡眠定时等；界面右上角问号随时重看——书架问号重看书架引导后，打开书会自动重放播放器引导；朗读界面问号直接重看播放器引导，也可在「阅读设置 → 新手引导」中打开
- **阅读体验**：27 款阅读主题分三类各 9 款——纯色（纸白、米黄、护眼、月白、天青、夜读、靛蓝、黛紫、纯黑省电）、渐变（森林、薄荷、蜜蜂、晚霞、海天、紫藤、雾灰、青瓷、绯纸）、矢量图案（竹影、涟漪、祥云、落樱、菱格、荷塘月色、燕剪春风、风吹麦浪、星野），图案为内联 SVG 矢量纹样，缩放清晰；主题、字号、语速各有独立面板；手机端可用正文两侧按钮翻页

## iOS 锁屏听书（iPhone 锁屏续读）

iPhone 锁屏后，浏览器通常会暂停网页里的系统语音与 Web Audio。书声在使用 **离线 AI 音色** 时，会把合成好的语音片段交给页面里的媒体元素播放，因此锁屏后朗读仍能继续。已在 iPhone（iOS 18）的 Safari 标签页和「添加到主屏幕」的 PWA 中实测通过。

使用方法：

1. 打开「朗读设置」，把「朗读引擎」切换为「离线 AI」
2. 下载并启用朗读内容对应语言的离线音色包：中文书下载中文音色，英文书下载 Kristin，中英混排建议两个都下载
3. 开始朗读后锁屏；解锁回到书声时，进度与高亮会同步到当前句

锁屏界面会显示书名与章节，并支持播放、暂停、上一句和下一句。需要注意：

- 系统语音在 iOS 锁屏后会被系统暂停，因此锁屏续读需要离线 AI 音色
- 英文段落如果走系统英文音色，默认会启用「锁屏跳过英文」：锁屏期间跳过英文，解锁后自动恢复并提示跳过段数；下载英文 Kristin 后，英文也由本机合成，不受该开关影响
- 其他浏览器与平台受各自后台策略影响，未做同等验证；系统内存紧张或标签页被回收时仍可能中断
- 建议把书声添加到主屏幕，减少浏览器标签页被系统回收的概率

## 中英混读：中文与英文离线音色包同时使用

书声会按语言自动切分中文和英文片段：中文交给所选中文音色，英文交给英文离线音色 Kristin；两种模型共享同一份 WASM 运行时，并运行在同一个 Worker 中，所以不需要为英文再下载一遍运行时，内存开销也低于再开一个朗读引擎。

- 英文音色包约 25.7 MB，包含 22.05 kHz 女声 Kristin 与约 16.8 万条的英文词典；未下载英文包、关闭「英文使用离线音色」或离线引擎启动失败时，英文会自动回落到系统英文音色
- 朗读英文前会做归一化：数字、年份、日期、时间、货币、小数、序数、常见缩写和符号转换成英文读法；词典里没有的生词按字母拼读，不会静默丢失
- 英文音量（60%–120%）与英文语速（0.6–1.4×）在总语速上叠加，离线英文与系统英文都生效
- 英文包基于 LibriVox 公有领域录音训练，可商用；具体许可见下方「音色包许可」

从「读音反馈记录」导出 JSONL 后，可汇总成读音词典候选：

    npm run reports:overlay -- pronunciation-reports-20261102.jsonl --out=scripts/out/overlay-candidates.txt

脚本只接受 2–4 字词组，单字语境会跳过，避免全局覆盖；合并前请人工复核。
轻声只能用 `src/core/tts/trainedNeutrals.v1.txt` 里声学模型训练过的音素：`tokens.txt` 为每个音节都准备了无调 token，但多数从未在训练语料中出现，直接写进覆盖表会发出怪音或让整字静音。`npm run audit:polyphones -- --overlay-only` 会列出违规条目，`npm run audit:coverage` 会把这类轻声与可补齐的缺口分开统计。

少数两字词读音正确、但声学模型会把第二音节压成近乎静音（漏字/怪音）。覆盖表在该词**之后**放一个静音引号 `"`（`tokens.txt` ID 7）作为时长边界：模型会把边界前的音节读完整（实测 `jian1` 从 35ms 恢复到 313ms），而停顿与原句自然停顿重合，词本身不会被拆开。它不算读音，审计、黄金集与回归快照都会忽略它。新增同类词时在读音**末尾**加一个 `"`。

两个已排除的位置：把边界放进词内（`zhi1 , jian1`）会让模型把词读断，听感是「选、择」；改用 blank `_`（ID 1）会被读成一个额外的短音节，听感是「多了一个音」。

**边界只能落在词的两端**（2026-11-11 起硬性规定）：

| 位置 | 写法 | 何时用 |
| --- | --- | --- |
| 词尾 | `之间 zhi1 jian1 "` | 词内后一个音节被压成近乎静音 |
| 词首 | `地盘 " di4 pan2` | 词内**前一个**音节被压短（「地」105ms→128/279ms），或中间音节被压（`占便宜 " zhan4 pian2 yi`，2026-11-11 起「宜」改轻声） |
| 两端 | `" di4 pan2 "` | 只有实测在**全部**真实语境都稳定时才允许；「地盘」的双端写法在「地盘很小」里会把两个字一起压没，因此被否掉 |

词内边界（`占便宜 zhan4 pian2 " yi2`）已**全面禁用**：它让「便」按短语末处理，时长被截断、上扬的调尾收不回来，用户听到的是「读了，但读音不准」——这是 2026-11-09 到 11-11 三次返工的直接原因。`npm run audit:omission -- --verify` 现在有策略检查，覆盖表里只要出现词内边界就判失败。

词首边界会把整词推进一个新短语，属于强改动，只允许用于 `src/core/tts/omissionCases.v1.jsonl` 里登记了「完整反馈原句 + 书中整块 + 真实 WASM 验收」的词。

**整词保护（抢词类）**：以上边界只能调整声学，不能保证词被命中。三条反馈原句在当前覆盖表下音素其实是对的（真实 WASM `debug=1` 日志确认 `占便宜 -> " zhan4 pian2 yi`、`地盘 -> " di4 pan2`），所以继续调边界不会解决音素连读问题。真正会复现用户错音的是「整词没被命中」：Matcha 前端按词典最长匹配，前一个汉字只要能与目标词首字组成更长的词条，整词覆盖就失效并落回单字读音；已初始化的 worker 若仍持有旧词典也会如此。

| 反馈 | 抢词 / 兜底示例 | 落回的单字读音 |
| --- | --- | --- |
| 会计读 huì | `学会计` → `学会 / 计`（真实 WASM 日志确认） | 会 `hui4` |
| 地盘的「地」读 de | `点地 / 盘`（跨词条目或旧 overlay） | 地 `de`（基础词典最后一条） |
| 「占便宜」漏「便」 | `会占便宜` / 拆成单字 | 便 `bian4` |

`src/core/tts/protectedWords.v1.txt` 登记必须整词命中的词；`SherpaDriver` 在合成前由 `pronunciationGuard.ts` 在这些词前插入零宽边界 U+200B。真实 WASM 日志确认该字符被当作 OOV 跳过（不产生 token、音频时长不变），但会强制前端从保护词重新开始最长匹配，因此不受整书 overlay、旧缓存构建或邻近抢词影响。`学会计` 另在覆盖表里整词钉成 `xue2 kuai4 ji4`，让黄金集与一致性快照这些纯词典门禁也能守住 `kuai4`。`SherpaDriver` 的运行时签名现在包含 overlay 指纹：词典一变就重建 worker，不会继续用旧词典朗读。`tests/browser/tts-diagnose.html` 的 P7–P11 / B10–B11 是修复前后可听对照。

## 读音自迭代闭环（P0–P4）

| 层 | 工具 | 职责 |
| --- | --- | --- |
| P0 | `npm run scan:risks` | 全书扫描「音素选错 / 数据漂移」，明确不覆盖声学问题 |
| P1 | `npm run rules:compile` | 把人工归因结论编译成整词覆盖行，默认只产候选 |
| P2 | `npm run audit:acoustics` | 真实 WASM 消融测音节时长，产出边界建议与例外表候选 |
| P3 | `npm run pronunciation:auto` | 自动发现 → A/B 验证 → 写回 → 重建快照 → 门禁 → 回归验证 |
| P4 | `npm run audit:omission` | 用**完整反馈原句**重建 token 序列，真实 WASM 验收每个音节是否真的读出来 |

此前 P0/P1/P2 都已落地，但它们都停在「产出候选、等人工复核」，而 P0 又明确
排除了「音素正确但被声学模型吞并/融合」的 C 类问题，P3 从未实现——所以健康度
报告即使 100 分，也只能说明流水线在运转，错读仍要靠用户逐个听出来再反馈。
「来到」听成「老」就是典型：基础词典的「到了 dao4 le」把「来」截成单字，
`lai2` 的声母 `l` 与 `dao4` 的韵母 `ao` 拼成模型训练过的 `lao`，P0/P1/P2
都看不到，也就不会自动报出来。

    npm run pronunciation:auto                        # 静态巡检全书，按风险排序
    npm run pronunciation:auto -- --measure           # 对高置信词做真实 WASM A/B
    npm run pronunciation:auto -- --measure --apply   # 自动写回 + 重建快照 + 全量门禁
    npm run pronunciation:auto -- --verify            # CI 门禁（不加载模型，秒级）

扫描器找出「最长匹配把前字截成单字，且前字声母 + 后字韵母是模型训练过的音节」
的组合，例如「来到了 → lao」「看到了 → kao」「回到了 → hao」。高置信条件
（后字韵母 `ao` + 后接轻声）才进入自动应用通道，其余只作为线索留档。
`--apply` 还要求：在 ≥2 条真实证据句上复验，平均均衡度提升 ≥20 且任一上下文
下降不得超过 20，每个上下文末音节 <350ms、最弱音节 ≥100ms，词长 ≤3；写回前
全书影响面 diff 零意外变化，写回后 `npm run audit:all` 全通过，否则自动回滚。
复验冲突的词（如「受到了」：+136.4 / -52.0）会撤销写入并保留为待复听线索。
每次修复都会写入 `src/core/tts/fusionFixes.v1.jsonl`；
`--verify` 会临时把这些词从词典里删掉重新扫描证据句，确保以后仍能自动发现
同一类问题，而不是只钉住用户报过的那一句。收敛趋势见
`scripts/out/auto-loop-history.jsonl`。

### P4：为什么「便」漏读被误判已修复三次

「正因如此，一些会占便宜的有钱人长期地用盐不给钱。」里漏读「便」，前两轮分别
加了词尾完成边界、又整个移除，都判定修复完成、9 项门禁全绿，但用户仍然听不到
这个字。真实原因有三层：

1. `scripts/audit-acoustics.mjs` 的验收用例手写了一段 **16 个 token、到「有钱人」
   就结束**的序列，把反馈原句后半句「长期地用盐不给钱」整个丢了。真实前端给声学
   模型的是 24 个 token 的完整序列，两次 A/B 测的都不是用户听到的那句话。
2. `--verify` 只断言 `recommendation === 'keep'`。而 `chooseVariant` 有 20 分的
   keep 余量，即使当前配置里还有 58ms 的被吞音节，也会照样判「keep」。
3. `acousticExceptions.v1.jsonl` 把该词留在 `pending-listening`，从未复听确认；
   黄金集只校验音素 `pian2`，音素一直是对的，所以全链路都看不见「没读出来」。

第一轮修复把完成边界放在 `pian2` 之后（`占便宜 zhan4 pian2 " yi2`），数字变好看了，
但 11-11 复听的结果是「便能听见了，读音不准」：边界在词内，等于把「便」按短语末处理，
时长只剩 221ms、上扬的调尾被截断。**词内边界本身就是错的**，它违反第 112 行写下的
「边界只放词尾」。真正的修复是词首边界：

    占便宜 " zhan4 pian2 yi       # 词首边界保留；「宜」第五次复听改轻声（见下节）
    地盘 " di4 pan2               # 地/盘 105/256 → 128/198ms（「地盘很小」58/128 → 279/337）

同时补了两条**结构性**防线：

    npm run audit:omission -- --verify      # 必需门禁，也由 audit:all 调用
    npm run audit:omission -- --measure     # 枚举全部完成边界位置做多上下文 A/B
    npm run audit:omission -- --apply       # 写回 + 追加案例 + 重建快照 + 全门禁

`omissionCases.v1.jsonl` 保存**完整反馈原句**，验收时现场用当前覆盖表重建运行时
token 序列，并断言：每个汉字恰好产出一个音素（截断的 token 序列必然失败）、
记录的修复没有回退、真实 WASM 下每个音节都在 100–350ms（被吞/吞并邻音即失败）、
以及**覆盖表里没有词内边界**。

关键是 `contexts` 字段：除了用户转述的那一句，还必须保存**前端真正送进声学模型的
整块**（按逗号合并到 12 个词之后的那一段）。「地盘」被误判修复两次，就是因为
`di4 pan2` 在用户复述的短句里听着没问题，而 App 实际发送的 20 音节整块里「地」
只有 105ms、另一个真实语境里只有 58ms。整块而不是整段：前端会把长段切成多块，
直接拿整段 token 去测反而比 App 更差。

全书扩散还找到代理指标未收敛的上下文（「把占便宜进行到底」）。它们按
`needs-listening` 登记：每轮门禁照样真实 WASM 测量并列出，但不据代理指标自动改表，
也不冒充「已修复」；复听有结论后才升级为硬性门槛。这样既不会掩盖分歧，也不会让
有争议的分数卡住发布。

### 2026-11-11 第五次复听：两个病根彻底分开

用户仍然听到「占便宜」漏「便」、「地盘」的「地」读成 de。上一轮把两句都当成
「长句压字」是错的。这一轮先做归因，结论正好相反：

| 词 | 单独念 | 语句重置 | 整句一次合成 | 病根 | 该改什么 |
| --- | --- | --- | --- | --- | --- |
| 占便宜 | 不对 | 不对 | 不对 | 音素串 `pian2 + yi2` 两个阳平连读合并 | 改音素 |
| 地盘 | 对 | 对 | 不对 | 长句韵律把词首音节压成轻声 | 改韵律 |

音素级诊断（`scripts/scratch/diagnose-pian2.mjs`、`analyze_pian2_f0.py`，真实 WASM）：
单独「便」`pian2` 是 1 段 319ms 的升调（F0 260→354Hz），音素本身是好的；
`pian2 + yi2` 只有 1 段 659ms 的连续升调，两个音节融成一个，所以「便」听不到；
换成标准轻声 `yi` 后回到 2 段独立浊音。覆盖表因此改成

    占便宜 " zhan4 pian2 yi      # 宜轻声 = 标准 pián·yi，也是词库「便宜」的原读

词首边界保留用于长句韵律（完整原句 `pian2` 279ms，去掉会涨到 406ms 与邻音合并）。
边界、停顿、拆词、语句重置都救不了连读合并 —— 这正是前四轮全在调声学却一直复发的原因。
同类词 `小便宜 / 捡便宜 / 讨便宜 / 贪便宜 / 便宜货` 当时在词库里仍是 `pian2 yi2`，
先登记为待复听扩散线索；下一节记录第六轮逐词做完真实语境验收后的结论（含
「便宜货」必须保留全调的实测例外）。

「地盘」相反：`src/core/tts/utteranceResets.v1.txt` 登记这类「韵律压字」词，
`pronunciationGuard.ts` 在词前插入 U+2060，worker 只对山岚（matcha）按该标记
把文本切成两段、分别合成后拼接（120ms 静音），让「地盘」落在新语句开头；其他音色
只把标记当 OOV 去掉，音频不变。零宽边界 U+200B 仍负责整词命中，两者作用层不同，
不互相替代。更长的复合词（「地盘之争」）不会被从中间切开。

真实文本路径的修复前后可听对照：`scripts/out/audio/fixes-20261111/listen.html`
（`node scripts/scratch/verify-listening-fixes.mjs` 重新生成）。改轻声后有一条书中
整块的三个音节同时 >350ms（418/360/384），不可能是互相吞并；按 `advisorySentences`
每轮照测并列出、待复听，不冒充硬性门禁通过，也不据代理指标自动改表。

## 2026-11-11 第六次复听：换思路，从「读哪个音」改成「重建运行时数据链路」

用户反馈：「便宜」词族（小便宜、捡便宜、讨便宜、贪便宜、便宜货）的「便」、
「地盘」词族（抢地盘、占地盘、地盘）的「地」，听到的既不是干净的 biàn / pián，
也不是 de / dì，而是一个怪异含混的音。前五轮都在「该读哪个音素、边界放哪里」
里打转，`pian2` 与 `di4` 一直是对的，所以黄金集、规则编译、回归快照连续判通过。

这次换了归因方向：不再猜音素，而是把 App 真正发出声音的那条数据链路逐词重建。

| 层 | 重建方式 | 复用 |
| --- | --- | --- |
| 词典合并 | `AiModel.ts` 合并人工表 + 整书自动生成 overlay → `worker.patchLexicon` 删同名基础行、按序追加（Matcha map **最后一行生效**） | `buildRuntimeLexicon()` |
| 运行时文本 | `preparePronunciationText()` 的 U+200B 整词保护 + U+2060 语句重置；worker 按 U+2060 分段各合成一次，拼 120ms 静音 | `appSegments()` |
| 前端 token | 只对**真正送进声学模型的那一段**做最长匹配，断言每个汉字恰好一个音素、原句未截断 | `sentenceTokens()` / `sentenceCoverage()` |
| 声学 | 逐音节消融测时长（100–350ms 判可听）+ `generateText()` 真实文本前端波形 | `createMatchaSynth()` |

### 此前修复未生效的三个可复现原因

1. **8 个词里 7 个从未进人工覆盖表。** 历史只有 `大便宜 / 占便宜 / 地盘 / 地盘之争`
   四行；五个「便宜」词在基础词典里全是 `pian2 yi2`，两个阳平连读融成一段长升调
   （修复前真实 WASM：捡便宜 255/93/267ms，「便」只有 93ms 被吞；贪便宜单独念只有
   1 段连续浊音）；`抢地盘 / 占地盘` 连整词行都没有，验收脚本直接报「无法构造
   token 序列」——它们从未被任何门禁测量过。
2. **覆盖表合并顺序让人工表在 App 里失效，而门禁看不到。** `AiModel.ts` 原来把人工表
   拼在整书自动生成 overlay **之前**，worker 后写覆盖：整书表一旦含同名词就生效；
   而审计侧 `parseOverlay` 是**首行生效**，永远读到人工表。pinyin-pro 对裸词「便宜」
   给 `bian4 yi2`（`scripts/out/audit-ming3.txt:445`），对词族给 `yi0`——`yi0` 既不在
   `tokens.txt` 也不在 `trainedNeutrals.v1.txt`，是未训练轻声 / 怪音。现由
   `mergeLexiconOverlays()` 去重并让人工表最后生效，运行时与审计模型读到同一行。
3. **验收没走 App 的真实文本路径。** 旧门禁用手抄的、可能截断的 token 序列，既不含
   U+200B / U+2060，也没对这 8 个词逐条做真实 WASM 音节可听性检查。长句一次合成
   25–30 音素时 `min_words_in_sentence=12` 会重新分句，单音素消融会给出负值或三个
   音节同时 >350ms；这类代理指标按项目惯例每轮照测并列出、待复听，不冒充通过。

### 解决方案与适用词条范围

| 类别 | 词条 | 处理 |
| --- | --- | --- |
| 纳入修复与逐词验收 | 小便宜、捡便宜、讨便宜、贪便宜 | 整词覆盖行，「便」`pian2`、「宜」改训练过的轻声 `yi`，并加入整词保护 |
| 逐词例外 | 便宜货 | 保留 `pian2 yi2 huo4`：第三音节打断连读，A/B 显示改轻声反让前两音节被吞（93/93/128ms），保留全调两种语境都稳定 |
| 纳入修复与逐词验收 | 抢地盘、占地盘 | 整词钉 `qiang3 / zhan4 di4 pan2` + 词尾完成边界 `"`；同步登记保护词表与语句重置词表 |
| 守住但不改 | 占便宜、大便宜、地盘、地盘之争、地点 | 既有修复不回退 |
| 完整句子 | 「正因如此，一些会占便宜的有钱人长期地用盐不给钱。」及书中整块 | 「便」= `pian2` 清晰读出，「长期地」的「地」仍是助词轻声 `de` |
| 明确排除 | 便宜从事 / 便宜施行 / 便宜行事（文言 biàn yí）、小便、状语助词「地」、单字「便 / 地」覆盖、其它含「地」词 | 逐条断言守住，不扩散 |
| 引擎范围 | 仅离线山岚（matcha） | 不改 piper 小雅 / 初晴 / AISHELL-3 随包词典，不改系统语音与英文音色 |

`抢地盘 / 占地盘` 必须**同时**进保护词表和重置词表：`applyUtteranceResets()` 会因
「更长的保护词」跳过 U+2060（`pronunciationGuard.ts:108`），只加保护词会让长句韵律
压字复发。词尾边界由四组真实 WASM A/B 选出：词首边界让「地」只剩 70ms，双端边界
在「占地盘」吞并邻音（465/302/407ms），词尾边界在两词 × 短句 / 整块四组里全部 normal。

### 逐条验证

`npm run audit:word-family`（`--verify` 已作为必需门禁接入 `npm run audit:all`）对

### 2026-11-11 第七轮：X便 + 宜 的抢词（不便宜 / 得便宜 / 就便宜 / 以便宜 / 趁便宜）

真实 WASM `debug=1` 日志（`scripts/scratch/tokenize-real-wasm.mjs`）显示，前端会在
「便宜」前一个字上先命中更长的 X便 词条，把「便」读成 `bian4`、把「宜」留成单字
`yi2`：

| 语境 | 修复前真实前端 | 修复后 |
| --- | --- | --- |
| 不便宜 | 不便 `bu2 bian4` + 宜 `yi2` | `bu4 pian2 yi` |
| 得便宜 | 得便 `de2 bian4` + 宜 `yi2` | `de2 pian2 yi` |
| 就便宜 | 就便 `jiu4 bian4` + 宜 `yi2` | `jiu4 pian2 yi` |
| 以便宜 | 以便 `yi3 bian4` + 宜 `yi2` | `yi3 pian2 yi` |
| 趁便宜 | 趁便 `chen4 bian4` + 宜 `yi2` | `chen4 pian2 yi` |

这不是「便宜」本身读错，而是最长匹配把「便」交给了更长的 X便 词条；把「便宜」
登记进保护词表会切断「占便宜 / 小便宜」的整词，所以只钉住实际会出现的三字组合，
并用排除项守住真正的 X便 + 宜：`方便宜人`（方便 + 宜人）、`便宜行事`、
`便宜从事` 仍读 `bian4`。逐词门禁扩到 81 项静态检查，5 个组合各有真实前端切分、
黄金集与回归快照用例。

## 全量历史递归自迭代

上一节的 P3 只覆盖了「音节融合」一类，之前修过的多音字、词尾边界、最长匹配
截走、短分句配置仍可能在新词/新书上复发。`npm run iterate` 把这些历史修复
**全部**纳入同一个闭环：

    npm run iterate                          # 全量历史重放 + 六族全书扩散
    npm run iterate -- --measure --apply     # 对边界族新候选做 WASM A/B 并写回
    npm run iterate -- --verify              # CI 门禁：历史基线全量重放

引擎从 `tests/fixtures/pronunciation-golden.jsonl`、`readingRules.v1.jsonl`、
`acousticExceptions.v1.jsonl`、`fusionFixes.v1.jsonl`、`omissionCases.v1.jsonl`
和整张人工覆盖表**自动**提取历史案例（当前 1570 条），逐条删除同批修复词条、重建「修复前词典」，验证
问题当时确实存在、现在已修好且词条未被漂移；案例清单不需要人工维护。

| 归因族 | 历史问题举例 | 全书同类自动发现 |
| --- | --- | --- |
| phone | 易得 de2、率意 shuai4、而为 wéi | 按规则词形（「易得」→「X得」）扩散，产出 2–4 字整词候选 |
| boundary | 最先 / 上天 / 地盘 / 应立即 | 扫描词典二字词，交给真实 WASM 多上下文 A/B |
| fusion | 来到了 / 看到了 / 回到了 | 前字声母 + 后字韵母可拼成合法音节的组合 |
| frontend | 应应立即 / 原原已 | 断言 `min_words_in_sentence=12` 与 matcha overlay 未漂移 |
| segmentation | 中都截走、整词钉住 | 覆盖词在全书出现却输给更长词条的线索 |
| omission | 占便宜漏读「便」 | 同字同音素位置 + 鼻韵尾/弱声母邻接，扩散到「捡便宜 / 小便宜」等，逐条跑完句 A/B |

每次自动写回都会同步进入规则资产、P3 资产与 P4 漏读案例表，下一次 `--verify`
自动把它们加入重放基线——历史只增不减，这就是「递归」：修一个问题，多一条永久
回归基线，并在新语料里继续扩散找同类。`npm run iterate -- --measure --apply`
会同时跑 P3 融合族与 P4 漏读族的多上下文 A/B，任何一条门禁失败都自动回滚。
该门禁已作为必需项接入 `npm run audit:all`。
产物与趋势见 `scripts/out/self-iteration.md` 和 `self-iteration-history.jsonl`。

唯一保留人工判断的是 **phone 族**：同一个字有多个正确读音（「应天 yìng」与
「应该 yīng」），音素对错没有客观代理指标，所以只产出批量候选并自动跑全书
影响面 diff，不自动写回；专名特例可在规则里标 `generalize: false` 禁止扩散。
但它也不需要「先听出来再逐条反馈」——引擎会主动列出全书同类位置，一次确认
一批即可。其余五族都能自动验证并写回。

## 隐私与安全

- 无后端：所有导入的电子书、阅读进度、设置仅保存在本机
- 离线朗读（中文与英文）都在本机合成，文本不会发给第三方语音服务
- 读音反馈默认仅保存在本机。主动点击「去 GitHub 提交」时，应用只预填所选段落、读音标记与音色/版本信息，需要你在 GitHub 页面确认后提交，内容将公开可见
- 电子书视为不可信输入：阅读 iframe 禁用脚本，图片、样式、字体仅允许 `data:` / `blob:`，默认阻止远程资源
- 单个文件导入上限 200 MB
- AI 模型下载后做 SHA-256 完整性校验

## 常见问题

### 书籍会上传到服务器吗？

不会。项目没有后端，EPUB、TXT 等书籍、阅读进度和设置只保存在浏览器本机（IndexedDB / localStorage）。

### 读音反馈会上传什么？

反馈记录先写入本机 IndexedDB，不会自动上传。只有点击「去 GitHub 提交」时，才会打开预填好的 issue 页面；其中包含所选段落、标出的字与正确读音、书籍指纹、音色包版本。书名可在提交前取消勾选；提交后内容公开可见。也可以在「读音反馈记录」中复制或导出 JSONL，自行交给开发者汇总。

### 可以离线听书吗？

应用壳和已下载的离线音色包可以离线使用。首次打开需要联网加载网页；使用离线音色前需在应用内下载音色包：中文音色约 65–131 MB，英文 Kristin 约 25.7 MB，另需约 15 MB 共享运行时（只下载一次，中英文音色共用）。系统语音是否可用离线取决于设备已安装的语音。

### 中英混排的书怎么朗读？

书声会按语言自动切分片段：中文用你选择的中文音色，英文优先用离线 Kristin。想全离线朗读中英混排，需要同时下载一个中文音色包和英文音色包；英文包未下载、关闭「英文使用离线音色」或离线引擎启动失败时，英文会自动改用系统英文音色。英文数字、日期、货币和缩写会转成英文读法，词典外的生词按字母拼读。

### 为什么英文部分没有声音或听不清？

英文可以使用离线音色 Kristin，也可以在设置里改用系统英文音色。

- 使用离线英文音色：在「英文朗读」中下载英文音色包（约 25.7 MB），确认「英文使用离线音色」已开启；离线引擎启动失败时会自动回落系统语音
- 使用系统英文音色：请确认设备安装了英文语音（iOS：设置 → 辅助功能 → 朗读内容 → 声音 → 英语；Android：在系统 TTS 设置中安装英语语音数据）。如果设备只有中文音色，英文部分可能无声

英文音量与英文语速可单独调节，对离线与系统英文都生效；系统语音音量上限是 100%，设置高于 100% 不会更响。

### 进度旁的「本章剩约 N 分钟」怎么来的？

书声会记录 AI 音色实际的合成速度与音频时长，再按剩余句子、中英文语速和停顿档位估算本章剩余时间。它是估算值，会随着朗读样本增多而更贴近实际。

### 为什么提示「合成速度偏慢」？

在性能较弱的手机上，离线 AI 音色可能来不及实时合成，播放会断续。连续多个句组偏慢时书声会提示一次，可以切换到系统语音，或关闭「连读模式」缩短等待。

### 为什么有些书没有封面？

书声会读取 EPUB、FB2、MOBI、AZW3 书内声明的封面；TXT 没有封面，会显示渐变书脊。书籍本身没有封面图、封面文件损坏或超过 12 MB 时也会使用占位。旧书架会在打开后自动补取一次封面。

### 支持 DRM 电子书吗？

不支持。Kindle、Apple Books 等带 DRM 的 MOBI、AZW3 或 EPUB 无法解析。

### TXT 小说怎么分章？

自动识别「第 X 章」「序章」「楔子」「前言」「后记」「番外」等常见标题；没有标题的长文本会按长度自动分节。

### 可以锁屏或后台播放吗？（iPhone 锁屏听书）

可以，但需要选择 **离线 AI 音色**。iPhone 锁屏后系统会暂停网页里的系统语音和 Web Audio，书声改用媒体元素播放离线合成的语音，因此能跨锁屏继续朗读。已在 iPhone（iOS 18）的 Safari 与主屏 PWA 中验证，锁屏界面可播放、暂停和切换句子。

系统语音模式在 iOS 锁屏后会停止；英文如果走系统音色，默认会按「锁屏跳过英文」处理，解锁后自动恢复并提示跳过段数。其他浏览器与平台受各自后台策略影响，未做同等保证。详见上方「iOS 锁屏听书」。

### 为什么锁屏后英文段落被跳过？

这是「锁屏跳过英文」在起作用，仅针对 iOS 锁屏、离线 AI 朗读、且英文使用系统英文音色的情况：系统语音锁屏后会停止，跳过英文可以避免朗读链卡住。解锁后会自动恢复英文朗读，并提示锁屏期间跳过的段数。可以在朗读设置里关闭这个开关；下载英文离线音色 Kristin 后，英文由本机合成，锁屏时不会被跳过。

### 怎么添加到主屏幕？

iPhone / iPad 用 Safari 打开后点「分享」→「添加到主屏幕」；Android 用 Chrome 菜单里的「安装应用」或「添加到主屏幕」。

### 跳过新手引导之后，还能再看吗？

可以。书架和朗读界面右上角都有问号按钮：书架的问号重看书架引导，并在你之后打开一本书时自动重放播放器引导；朗读界面的问号直接重看播放器的分步引导。也可以在「阅读设置 → 新手引导 → 查看」中打开。引导是否看过只记录在本机浏览器，清除站点数据后会再次自动出现。

## 已知限制

- 睡眠定时仅对当前阅读页生效，刷新或返回书架后取消
- 锁屏续读依赖离线 AI 音色；系统语音在 iOS 锁屏后会被系统暂停
- 锁屏续读已在 iPhone（iOS 18）Safari 与主屏 PWA 验证，其他浏览器和平台受各自后台策略影响，未做同等保证
- 系统内存紧张、手动关闭页面或标签页被回收时，锁屏朗读仍可能中断
- 同时驻留中文与英文离线音色会增加内存占用，内存较小的设备可以只下载常用语言
- 手机上点按正文用于跳转朗读，暂不能长按选中正文文字
- GitHub Pages 项目站点无法在域名根目录提供 `robots.txt`，搜索引擎抓取请以 sitemap 提交和页面元数据为准
